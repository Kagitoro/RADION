# Late Set

Ночной DJ-симулятор от первого лица на Godot 4.

## Запуск

1. Клонируйте репозиторий в отдельную папку.
2. В менеджере проектов **Godot 4.7** (или новее) нажмите **Import** и выберите `project.godot`.
3. Дождитесь первого импорта ассетов и нажмите **F5**.

При первом запуске кнопка «Начать игру» запускает сюжетное вступление. Положение игрока, сюжетный прогресс и выбранная папка с музыкой сохраняются локально у каждого игрока.

## Управление

- **WASD** и мышь — движение и обзор. **Shift** — бег, **Space** — прыжок.
- **E** — взаимодействие. **Esc** — пауза. В меню паузы **«Начать заново»** сбрасывает сюжет, деньги и покупки и запускает игру с начала (настройки, папка с музыкой и расстановка дома сохраняются).
- **ЛКМ по FLX4** или **C** рядом с пультом — режим сведения. Через ноутбук можно выбрать локальные MP3, WAV и OGG.
- **J** в клубе — начать смену. **H** — поручить ситуацию персоналу.

- **E** у прилавка Night Shop — купить энергетики, пиво и сигареты. Магазин находится слева от клуба после перехода через дорогу. **R** — выпить энергетик, **B** — пиво, **N** — сигарета.

- Спуск **Subway · 8 AV** находится за Night Shop. На платформе **E** при взгляде на персонажа даёт ему $2 из игровых денег.

Все клавиши заданы действиями в **Project Settings → Input Map** (`move_forward`, `interact`, `pause`, `open_mixer` и т. д.), поэтому их можно переназначить без правки кода. Движение, прыжок, взаимодействие и пауза работают и с геймпадом.

## Структура кода

**Корень и общие сервисы**
- `home.gd` (`Home`) — корневая сцена: загружает дом из `assets/layout.json` и создаёт все системы. Короткие ссылки: `home.club`, `home.shop`.
- `game_events.gd` — autoload `GameEvents`, шина сигналов: `GameEvents.notify("…")` для сообщений игроку, `GameEvents.refresh_hud()` вместо прямых вызовов HUD.
- `balance.gd` (`Balance`) — все параметры баланса (атмосфера, энергия клуба, штрафы, тайминги). Сложность настраивается здесь.
- `game_settings.gd` (`GameSettings`) — настройки игрока между запусками (язык).
- `game_reset.gd` (`GameReset`) — «Начать заново»: список файлов прогресса и перезапуск сцены. Новый файл прогресса добавляйте в `GameReset.progress_files()`.
- `save_paths.gd` (`SavePaths`) — единственное место, где решается, куда пишутся файлы. Тестовые запуски пишут в `user://smoke_test/` и не трогают сохранения игрока.

**Редактор дома** (режим разработчика): `home_controls.gd`, `room_layout.gd`, `project_storage.gd`, `target_frames.gd`, `plan.gd` + `plan_snapping.gd`, `hud.gd`, `openings.gd`, `construction.gd`, `seams.gd`, `scene_finish.gd`.

**Игровой процесс**
- `night_game.gd` — взаимодействия игрока, разговоры, пауза; `night_world.gd`, `night_district.gd` — улица; `subway_station.gd` (`SubwayStation`, `home.subway`) — станция 8 AV с поездом и пассажирами.
- `deck_host.gd` (`DeckHost`) — общий базовый класс площадок с пультом: `party.gd` (`Party`, домашняя вечеринка) и `nightclub.gd` (`Nightclub`). У `Party` есть публичный API (`consume`, `route_to`, `has_walkable_area`…), внутренние модули `party_consumables.gd` и `party_navigation.gd` снаружи не трогайте.
- `dj_station.gd` (`DJStation`) — деки, микс, эффекты; `dj/` — библиотека музыки, фото-контроллер FLX4, экран ноутбука, крутилки и осциллограф.
- `club_shift.gd`, `street_shop.gd`, `arrival_intro.gd`, `main_menu.gd`, `player.gd`, `party_guest.gd`, `guest_model.gd`, `party_events.gd`.

**Руки, предметы и эффекты** — `scripts/fx/`
- `fp_view_model.gd` (`FPViewModel`, `player.view_model`) — руки от первого лица на камере: инерция при повороте, покачивание при ходьбе, дыхание. Действия — ресурсы `Animation`, каждое на свежем `AnimationPlayer`.
- `fp_hand.gd` (`FPHand`) — рука со скелетом (`assets/fp/arm.glb`), позы хвата (`bottle`, `can`, `pinch`, `lighter`, `point`, `fist`…) и подгонка пальцев под бутылку/банку, чтобы они не проходили сквозь предмет.
- `fp_props.gd` (`FPProps`) — пиво, банка VOLT, сигарета, зажигалка, пачка ORION и упаковка пива из `assets/fp/*.glb`; версии для рук и для мира.
- `fp_effects.gd`, `fp_sounds.gd`, `screen_fx.gd` — частицы (дым, искры, брызги), синтезированные звуки и экранные эффекты опьянения, тошноты и энергетика.
- `visual_quality.gd` (`VisualQuality`) — SSAO/SSIL/SSR, свечение, объёмный туман, тени ламп и мелкая фактура однотонных поверхностей. Уровни графики (Низкая/Средняя/Высокая, в настройках) включают эффекты и задают бюджет теней: тени получают 0/3/5 ламп, чей свет попадает в кадр (лампы за стеной — в последнюю очередь), тень плавно появляется и гаснет (`shadow_opacity`), без PCSS (`light_size = 0`).
- `house_occlusion.gd` (`HouseOcclusion`) — окклюдеры-коробки из коллизий сплошных стен дома (стены с проёмами уже разбиты на коробки вокруг дверей и окон). Без них из коридора рисовалась вся улица сквозь стены (~7000 draw calls вместо ~1700). Требует `rendering/occlusion_culling/use_occlusion_culling`.
- Замер производительности: `godot --path . -- --visual-tour=perf` печатает строки `PERF` — GPU/CPU-время кадра, draw calls и примитивы по комнатам, цену каждого эффекта и уровня графики (vsync выключается на время замера).
- Хореография пива, энергетика, сигареты (прикурить, затяжка N, K — выбросить) — в `party_consumables.gd`; рвота — `Player.vomit()`.

**Свет в доме** — `assets/house_lights.tscn`: откройте сцену в редакторе Godot (дом виден подложкой только в редакторе), перетаскивайте лампы в 3D-окне — сфера радиуса и конус прожектора показывают, куда достаёт свет; цвет, яркость (`light_energy`) и радиус меняются в инспекторе. Сохраните сцену — игра читает свет оттуда (массив `lights` в `layout.json` больше не используется). Метаданные `fixture` (id предмета, например `base-117` — люстра) привязывают лампу к светильнику: она едет вместе с ним; лампы без привязки переезжают со своей комнатой. Тени не включайте — ими управляет игра (`VisualQuality`). Новую лампу добавляйте копией существующей (Ctrl+D).

**Стиль low poly для всего мира** — одна стилистика с руками и предметами от первого лица:
- Модели: аддон `addons/lowpoly_import` (включён в `project.godot`) перестраивает сетки при импорте. Параметры в `.import` каждого `.glb` (или во вкладке «Импорт»): `lowpoly/flat` — плоское затенение, одна нормаль на грань; `lowpoly/detail` — доля треугольников после упрощения (meshoptimizer); `lowpoly/max_error` — предел искажения формы. Имена узлов, кости и анимации не меняются; у мешей с blend shapes только плоское затенение, без упрощения. Карты нормалей убираются, материалы матовые. Сейчас: дом 0.6 (322k → 178k треугольников), клуб, улица и машины 0.5–0.6, персонажи и мелкие предметы — только плоское затенение. Чтобы переимпортировать модель, удалите её `.scn` из `.godot/imported/` и запустите `godot --headless --path . --import`.
- Текстуры дома: `Blender -b --python tools/blender/stylize_textures.py` — уменьшает текстуру до крупных форм, сводит к 7–16 цветам (k-means) и чистит фильтром большинства: ровные заливки вместо шума. Оригиналы лежат в `art_source/` (Godot его игнорирует), проход всегда начинается с них.
- Код: `VisualQuality.surfaces()` делает однотонные материалы матовыми без шума и рельефа, а сферы, цилиндры, капсулы и торы из кода заменяет гранёными копиями с малым числом сегментов; стены — ровная краска (`VisualQuality.plaster`).

**Модели и анимации рук** — `assets/fp/`
- Модели собирает Blender-скрипт `tools/blender/build_fp_assets.py` в стилизованном low poly с плоскими гранями (рука: шестигранные пальцы с общими кольцами на суставах, ладонь — выпуклая оболочка из опорных точек, 17 костей, ногти-пластины, гранёный рукав с манжетой; предметы с теми же именами частей, что ждёт код; у банки blend shape `Crushed` для смятия). Исходники — `assets/fp/source/` (скелет руки и текстуры этикеток выгружает `godot --path . -- --visual-tour=export`). Пересборка: `Blender -b --python tools/blender/build_fp_assets.py [-- arm bottle can …]` (имена после `--` выбирают модели, `FP_OUT=<папка>` пишет пробную сборку мимо `assets/fp`; скрипт сбрасывает сцену, поэтому запускайте его только в фоне `-b`, не в открытом Blender), превью — `tools/blender/preview_fp_assets.py`.
- Анимации действий лежат в `assets/fp/anims/{beer,energy,light,puff,stub}.tres` и ключуют каждую кость обеих рук. Если файла нет, действие собирается кодом в `party_consumables.gd`.
- **Правка вручную:** откройте `assets/fp/preview/<действие>.tscn`, выберите `Actions` → анимацию внизу, перемотайте на нужный момент, выделите `Arm/ArmRig/Skeleton3D`, выберите кость (`index_1…3`, `thumb_1…3`, `forearm`…), поверните и нажмите ключ у дорожки кости. Сохранение пишет прямо в `.tres`, игра подхватит его сама.
- `godot --path . -- --visual-tour=bake` заново записывает все `.tres` и превью из кода — **это перезапишет ручные правки**.
- Проверить правки поз в коде без перезапекания: добавьте к туру `--no-baked` (например, `godot --path . -- --visual-tour=pose,grip --no-baked`).

Рендерер — Forward+ с автоматическим откатом на OpenGL (`rendering_device/fallback_to_opengl3`), на нём часть эффектов отключается.

**Интерфейс** — `ui/`: сцены `main_menu_screen`, `pause_menu`, `backpack_panel` (инвентарь игрока, Tab), `shop_panel`, `party_status`, `club_shift_panel`, `interaction_hints`, `intro_overlay`, `inventory_window` (инвентарь редактора дома), `held_card`, `target_card`, `dj/laptop_panel`, общая тема `theme.tres` и фабрика виджетов `UIKit`.
- Стиль — low poly: панели и кнопки со срезанными под 45° углами и толстой нижней гранью, палитра и стили в `UIKit` (`INK`, `NIGHT`, `AMBER`, `PINK`, `CYAN`…), заголовки и кнопки шрифтом Russo One (`assets/fonts`, OFL). Тема — тема проекта по умолчанию (`gui/theme/custom`); после правки `UIKit` пересоберите её: `godot --headless --path . --script res://tools/build_ui_theme.gd`.
- Варианты типов темы: `DisplayLabel` (заголовок), `KeyCap` (клавиша), `HudBadge` / `HudNotice` / `HudObjective` (плашки HUD), `MenuButtonBig` (скошенная кнопка меню). Готовые виджеты: `LowPolyBackdrop` (фон из треугольников), `LowPolyEqualizer`, `KeyHints` (строка «клавиша действие · …» в виде клавиш), `Crosshair`, `SettingsBox` (общие настройки паузы и главного меню, сохраняются в `GameSettings`), `MenuFx` (фокус = наведение, появление окон). Сцены только показывают данные и сообщают о действиях сигналами — логика остаётся в скриптах систем. Новые экраны делайте сценами по этому образцу. В коде намеренно остались: фото-контроллер FLX4 (кнопки расставлены по координатам фотографии), 3D-экран ноутбука и нижняя панель плана (строится в циклах из данных).

У каждого скрипта есть `class_name`, поэтому для ссылок между системами используйте типы (`var home: Home`), а не `preload`.

## Тесты

```sh
godot --headless --path . -- --smoke          # все проверки, код выхода 0 = успех
godot --path . -- --visual-smoke              # скриншоты экранов в user://smoke_test/ui-*.png
```

`tests/smoke_runner.gd` запускает два набора:
- `home_smoke_test.gd` — редактор дома: библиотека, взятие и размер предметов, undo, сохранение/загрузка, перемещение комнат, план этажа, инвентарь, привязки клавиш, меню паузы.
- `gameplay_smoke_test.gd` — пульт (ноутбук, контроллер по C, Esc, деки, пауза, перемотка), домашняя вечеринка и гости, магазин, пиво и сигарета, библиотека музыки, клубная смена, метро (платформа, прицел, помощь $2, поезд), главное меню, вступление, выбор языка, полнота перевода. Последним идёт полный цикл «Начать заново»: сцена перезагружается, и тест проверяет новую игру.

Для работы над графикой есть скриншот-тур: `godot --path . -- --visual-tour` (или `--visual-tour=rooms,street,shop,club,actions,pose,grip,plan,sounds`) — кадры комнат, улицы, магазина, клуба и покадровые снимки анимаций рук попадают в `user://smoke_test/tour-*.png`. Тур считается тестовым запуском и не трогает сохранения.

Любая ошибка движка или скрипта во время тестов (`ErrorCollector`) тоже считается провалом. Запускайте тест перед каждым pull request, а для новой механики добавляйте проверку в `gameplay_smoke_test.gd`.

## Локализация

Исходный язык — русский, есть английский перевод `locale/en.po`. Игрок выбирает язык в меню паузы (**Язык / Language**: системный, русский или English). Выбор применяется сразу, без перезапуска, и сохраняется (`GameSettings`, файл `settings.cfg`). При «системном» языке без перевода (например, украинском) показывается русский оригинал (`locale/fallback="ru"`).

Чтобы смена языка работала на лету, интерфейс всегда строится на русском, а элементы интерфейса переводят свой текст сами. Поэтому не сохраняйте переведённый текст в переменные заранее: храните ключ (русскую фразу) и вызывайте `tr()` при показе — как `PartyGuest.introduction()`.

Видимый игроку текст обёрнут в `tr()` целыми фразами с `%s`/`%d` (не склеивайте перевод из кусков). Тексты в сценах переводятся автоматически. После изменения текстов обновите шаблон: `python3 tools/extract_pot.py`, затем добавьте новые строки в `en.po` (например, в Poedit через «Обновить из POT»). Подписи объектов (`label`) — это данные сохранений: переводите их только при выводе на экран.

## Известные проблемы

- При выходе Godot 4.7.2 иногда пишет `ObjectDB instances were leaked` (`AudioStreamMP3`). Это ошибка движка, а не игры: она воспроизводится в пустом проекте — см. `tools/godot_audio_leak_repro/`. На игру не влияет.

## Работа вдвоём

Бинарные ассеты (`.glb`, `.png`, `.jpg`, `.mp3`, `.wav`, `.ogg`) хранятся в **Git LFS**. Один раз на каждом компьютере:

```sh
brew install git-lfs     # Windows: https://git-lfs.com
git lfs install
git lfs pull             # если репозиторий уже был склонирован
```

Без этого вместо моделей и звуков придут текстовые файлы-указатели, и игра не откроется.

Создавайте отдельную ветку на каждую задачу и открывайте pull request в `main`. Перед началом работы обновляйте локальную `main`. Договаривайтесь заранее, если обоим нужно менять одну сцену `.tscn` или бинарную модель `.glb`.

`.godot/` Godot создаёт заново на каждом компьютере. Исходные ассеты, файлы импорта и `.uid` хранятся в репозитории. Сведения об ассетах и музыке лежат рядом с файлами в `assets/`.
